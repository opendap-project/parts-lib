## Summary

The RK860-0 is the I2C-programmable buck that supplies vdd_cpu to the RK3566 CPU cluster (BOM v1 line 3, *Proposed*). It replaces the RK860-2 of the BOM draft because the RK860-0 is the part on the RK3566 reference design used for comparison (Radxa ZERO 3W) (BOM v1 §0 item 6). It runs from VSYS and outputs 0.80–1.15 V, with a design maximum of 3 A (est.) and about 0.15 A (est.) during screen-off playback (power tree v0 §2, §3). Everything in this sheet is **UNVERIFIED**.

## Linux driver

- BOM v1 line 3: *mainline + Debian*, driver `fan53555`, compatible `rockchip,rk8600`, `CONFIG_REGULATOR_FAN53555=m`.
- From knowledge of the mainline tree, not re-read in this session (**UNVERIFIED**): the driver is `drivers/regulator/fan53555.c`, which handles the Fairchild FAN53555 family, Silergy SYR82x, TCS4525 and Rockchip RK8600/RK8601 (`rockchip,rk8600`, `rockchip,rk8601`) and RK8602/RK8603 (`rockchip,rk8602`, `rockchip,rk8603`, separate register layout). The device-tree property `fcs,suspend-voltage-selector` selects which VSEL register holds the suspend voltage.
- The mapping of the RK860-**0** marking to the `rockchip,rk8600` compatible is taken from BOM v1 and is **UNVERIFIED**; the RK860-2 alternative uses `rockchip,rk8602` with a different OTP default and register map (BOM v1 line 3).
- Second source Silergy SYR827PKC uses the same driver (BOM v1 line 3; mainline Orange Pi 3B device tree).

## Design notes for the T1

- The OTP boot voltage of the populated variant must match the RK3566 vdd_cpu default; RK860-0 and RK860-2 differ (BOM v1 line 3). Confirm on the reference board before ordering.
- The I2C address 0x40 shares I2C0 with the RK809 (0x20); no clash at the stated addresses. The INA236 monitors at 0x40–0x43 are on I2C1, not I2C0 (BOM v1 line 54).
- Inductor and capacitors follow the Radxa ZERO 3W reference until a datasheet exists (BOM v1 line 4).
- Thermal: RK860 next to the RK3566, RK809 and charger in a sealed body is not modelled (power tree v0 risk 10).
